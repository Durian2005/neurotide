# NeuroTide

NeuroTide 是一个纯前端的个人数据情绪地图：导入聊天记录 TXT 后，在浏览器本地解析文本、按天聚合情绪，并通过日历热力图和当日趋势图展示结果。

## 功能

- 支持拖拽或选择 TXT 聊天记录，按日期生成情绪日历
- 支持上传单张聊天截图，本地 OCR 后校对并查看该图的情绪词统计
- 支持为当前截图用日期滚轮添加日期标记
- 支持导入 TXT、CSV 或 JSON 时间坐标，在当天时间轴上查看情绪曲线
- 支持载入内置合成示例数据
- 按天计算情绪值并显示日历热力图
- 支持近 3 个月、近半年和全部数据筛选
- 查看某一天的情绪趋势、主导情绪词和原始记录
- 「趋势与洞察」视图：7 日均线与线性趋势、连续低落 / 连续积极天数、星期×时段分布、区间 A/B 对比、情绪词云
- 在本机保存多份数据集，重新打开页面自动恢复上次会话
- 导出完整报告 PNG（含标题与概览）、热力图 PNG、日粒度 CSV、可重新导入的 JSON 备份
- 日历支持完整键盘操作与屏幕阅读器播报，另有色觉辅助与高对比开关，窄屏自动折叠侧栏
- 所有解析和计算均在浏览器中完成

## 数据格式

截图模式的日期标记通过界面内的“截图日期”滚轮选择，不会改变原始图片，也不会自动写入聊天记录。

聊天记录 TXT 会自动嗅探格式，支持下面 4 种常见导出形态，无需手工改造：

```text
[2026-09-26 08:12:00] 我: 今天的天气很好，心情很轻松。
2026-09-26 08:12:00 我: 今天的天气很好，心情很轻松。
```

```text
[2026-09-26 08:12:00] 我
今天的天气很好，心情很轻松。

2026-09-26 08:12:00 我
今天的天气很好，心情很轻松。
```

要点：

- 日期分隔符支持 `-`、`/`、`.`，秒可省略；昵称与内容之间支持 `:` 或 `：`
- 「时间行 + 换行内容」形态下，不带时间戳的后续行会并入上一条记录
- 分隔线、装饰性标题行（如 `=== 聊天记录导出 ===`）与仅有日期的标题行会被自动跳过
- 编码自动识别：UTF-8（含 BOM）、UTF-16LE/BE、GBK / GB18030
- 导入后会显示识别到的格式、编码、记录数与续行数；日期不合法（如 2 月 30 日）或无法识别的行会单独提示，不计入统计
- 单文件上限 20 MB，超过 5 MB 会提示解析需要数秒
- 也可直接导入本应用导出的 JSON 备份（扩展名 `.json`）来还原数据集

时间坐标文件可选导入以下格式：

```text
[08:30] 今天心情很开心
[12:45] 工作有点压力
[19:20] 晚上感觉轻松
```

CSV 使用 `time,text` 两列；JSON 可以是数组，或使用 `{"points":[{"time":"08:30","text":"..."}]}` 结构。坐标文本会复用本地情绪词典，在当天 `00:00–24:00` 时间轴上绘制曲线。

## 计分模型

情绪值全部由本地词典计算，规则透明、可复核：

- 词典由「积极 / 消极 + 强度权重」构成，命中即按权重累加，不再是命中即 ±1
- 识别否定词（`不`、`没`、`无`、`毫无` …），命中后翻转极性并乘衰减系数，例如「不开心」会计为消极
- 识别程度副词（`非常`、`很`、`有点`、`太` …），按倍数放大或削弱权重
- 采用最长匹配优先与邻接屏蔽，避免「积累」被「累」误命中这类子串问题
- 归一化口径统一：单条记录压缩到 `[-1, 1]`，当日分值 = 该日各条记录分值的平均；因此切换「近 3 月 / 近半年 / 全部」不会改变同一天的历史数值

上述分值为词典规则的统计结果，不代表临床结论，仅供参考。

## 趋势与洞察

主视图可切换到「趋势与洞察」。这里给出的每个指标都写明了口径，避免自我观察时误读：

| 指标 | 口径 |
| --- | --- |
| 每日情绪值 | 该日各条记录分值的平均；没有记录的日子**不算 0**，而是留空 |
| 7 日均线 | 按日历窗口滑动，窗口内只统计有记录的天；窗口内全无记录时为断点。折线在缺口处断开，不把「没记录」连成直线 |
| 线性趋势 | 对区间内有记录的天做最小二乘拟合（x = 距首日天数），每 30 天的变化量小于 0.06 视为持平 |
| 连续低落 | 相邻两天的日期必须正好相差 1 天；中间断更即断开——缺记录不等于情绪好转 |
| 星期×时段 | 按 4 小时分 6 个时段，颜色表示该格平均情绪值、数字表示记录条数；最好/最差时段要求该格至少 3 条记录，避免单条记录就下结论 |
| 区间对比 | B = 最近 N 天、A = 紧邻其前的 N 天（N 取总跨度一半，限制在 7–90 天）；任一侧完全没有记录时不出对比，否则「从无到有」会被误读成情绪突变 |
| 词云 | 字号按出现频次缩放（平方根压缩，避免高频词压倒性变大），颜色表示极性 |

这些统计同样只在浏览器内计算，不会上传任何数据。

## 本地保存与导出

数据保存在浏览器本机，不经过任何服务端：

- 导入的聊天记录会自动保存为本机数据集，重新打开页面即恢复上次会话；同名文件会更新而不是新增副本
- 可在左侧「本地数据集」中列出、切换、删除，或一键清空全部本机数据
- 可在同一位置关闭「保存到本机」，此时导入的数据仅在当前会话有效
- 单文件上限 20 MB；`IndexedDB` 无单条硬上限，`localStorage` 兜底时约 2 MB

导出提供四种产物：

| 产物 | 内容 | 用途 |
| --- | --- | --- |
| 完整报告 PNG | 标题、数据区间、概览卡片、热力图、图例、页脚 | 直接放进报告或课堂演示 |
| 热力图 PNG | 热力图本身 | 需要原图时使用 |
| 日粒度 CSV | 日期、情绪值、加权计分、记录数、命中数、主导词 | 表格软件二次分析（含 UTF-8 BOM 与 CRLF，中文不乱码） |
| JSON 备份 | 原始文本 + 日粒度结果 + 计分口径 + 分析摘要（趋势 / 连续区间 / 星期×时段 / 词云 / 区间对比） | 备份与迁移，可直接拖回应用还原 |

CSV 导出的是当前筛选范围内的数据；JSON 备份内嵌原始文本，因此换一台机器重新导入即可完整还原。

## 性能与规模化

纯前端意味着所有计算都在浏览器主线程上，所以规模化时的目标不是「跑得更快」，而是**别把页面卡住**。两条关键路径做了处理。

**导入大文件：分片解析 + 进度**

解析 5 万条记录实测约 280 ms；按 20 MB 的文件上限换算，最坏情况约 60 万行、两三秒。同步跑完会让页面在这几秒里完全无响应 —— 连「正在解析…」都显示不出来，因为提示本身也要等主线程空闲才能绘制。

现在超过约 80 万字符（≈2 万行）的文件走分片路径：每 4000 行一片，片间让出主线程，并上报进度，文件区显示百分比与进度条。分片只改变「何时执行」、不改变处理顺序，因此结果与同步路径逐字段一致 —— 测试里用「1 行一片」把每条记录都切开，再逐字段比对两种路径的输出。

> 让出主线程用的是宏任务而不是 `scheduler.yield()`。后者把续行排成 user-blocking 优先级，会持续插队 React 的渲染调度，实测表现为进度条**一次都不出现**（`setProgress(0)` 与收尾的 `setProgress(null)` 被合并成同一次渲染）。

**打开某一天：分批渲染消息列表**

同一天的消息可能极多（群聊刷屏、攒了很久才导出一次）。原先当日详情把消息全量渲染成 DOM，实测一天 5 万条会产生约 **40 万个节点、单次阻塞主线程 2.4 秒**。

现在首批渲染 120 条，滚到底部自动续载下一批（同时保留一个显式按钮作为兜底），高亮分段也只对已显示的条目计算。同样一天 5 万条：

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 打开当日详情 | 2.7 s | **95 ms** |
| 打开后 DOM 节点 | 406,480 | **1,372** |
| 单次最长阻塞 | 2,398 ms | **64 ms** |

**为什么不用 Web Worker**：产物是单文件、通过 `file://` 双击打开，而浏览器会拦截 `file://` 下的 blob worker，所以没法把解析挪到别的线程 —— 片间让出主线程是能达到同样效果的可行做法。

## 无障碍与响应式

日历热力图用 Canvas 绘制，但**画布只是视觉层**：真正的语义结构是一个同源生成的 `role="grid"` 隐藏网格，逐格给出日期、星期、情绪值与记录数，因此屏幕阅读器能完整读出整张日历，而不只是「一张图片」。

日历的几何会自动适配画布：**月份块按画布高宽比折成多行**，取「能让格子最大的那种折法」。全部 10 个月排成一行时是一条 52 周 × 7 行的窄带，格子只能到 12–14px；折成 2–3 行后周长减半，格子能到 34px。块行内列号独立编号，语义网格的 `aria-rowcount` = 7 × 块行数，与视觉行一一对应。画布高度按内容裁剪（不铺满容器），多余高度不会画进画布，因此导出的报告 PNG 也不会被空白按比例压扁。

聚焦日历后可用以下按键操作：

| 按键 | 行为 |
| --- | --- |
| `Tab` | 聚焦日历（出现青色焦点框与虚线游标格） |
| `←` / `→` | 前 / 后一天 |
| `↑` / `↓` | 前 / 后一周 |
| `Home` / `End` | 跳到区间首日 / 末日 |
| `PageUp` / `PageDown` | 上 / 下一个月（按目标月实际天数收口，不会溢出到再下个月） |
| `Enter` / `空格` | 打开游标所在日期的详情 |
| `Esc` | 关闭当日详情；窄屏下同时用于收起侧栏抽屉 |

其余无障碍与自适应行为：

- **色觉辅助**（侧栏「无障碍」）：只给热力图每格叠加方向字形（`▲` 积极 / `▼` 消极 / `·` 中性）与强度条（长度 = 超出中性带的绝对幅度），配色不变；星期×时段表本来就有条数数字，也一并带上方向字形。情绪方向不再只由色相承担
- **高对比**：界面文字由 `slate-500/600` 提升到 `slate-200/300`，面板描边加粗；图表改用高对比配色，消极色由 `#1e3a8a` 抬到 `#60a5fa`（对 `#0f172a` 背景的对比度由约 1.8:1 提升到约 7:1）。该配色把混合下限抬到 0.78，颜色因此不再承载幅度，所以热力图会同时显示强度条（但不加字形）
- 两个开关互不重叠：色觉辅助管「形状通道」，高对比管「亮度与配色」，可单独使用，也可同时开启
- **焦点可见**：所有可交互元素统一使用青色描边，不依赖浏览器默认焦点环
- **响应式**：≥1024px 时侧栏常驻（宽度取窗口的 30%，限制在 340–460px）；更窄时折叠为抽屉，由主区左上角的「控制面板」按钮打开，点遮罩或按 `Esc` 关闭。当日详情面板在窄屏由右侧浮层改为底部抽屉
- **减少动效**：遵循系统的 `prefers-reduced-motion` 设置（由 Framer Motion 的 `MotionConfig` 与 CSS 媒体查询共同处理）

## 本地运行

环境要求：Node.js 22 或更高版本（Vite 8 要求 Node 20.19+ / 22.12+）。

安装依赖：

```bash
npm install
```

启动开发服务器：

```bash
npm run dev
```

构建生产文件：

```bash
npm run build
```

构建结果会输出到 `dist/index.html`。日历模式的核心页面会内联到单个 HTML 中；截图 OCR 模式还需要同目录下的 `dist/ocr/` 本地资源，因此请使用项目根目录的 `open-neurotide.bat` 或下面的预览命令通过本地 HTTP 服务打开。

预览生产构建：

```bash
npm run preview
```

`open-neurotide.bat` 不依赖 Node 或 npm：它调用 `scripts/serve.ps1` 起一个只监听 `127.0.0.1` 的本地静态服务器，关闭窗口即停止。

## 打包分发

```bash
npm run package          # 用现有 dist/ 打包
npm run package -- --build   # 先构建再打包
npm run package -- --zip     # 额外产出 zip
```

产物在 `release/`（已加入 `.gitignore`，不进git 历史；对外分发建议走 GitHub Release 附件）：

| 产物 | 体积 | 用途 |
| --- | --- | --- |
| `neurotide-lite.html` | 约 527 KB | 单文件，双击即用，**不含截图 OCR** |
| `neurotide-full/` | 约 9.5 MB | 完整目录：`index.html` + `ocr/` + 启动器，解压即用 |

`manifest.json` 记录了各产物的 sha256，便于分发后校验。

**为什么拆成两半**：页面本身是单文件、可以 `file://` 直接打开，但截图 OCR 需要浏览器独立请求 `worker.min.js` / `tesseract-core-lstm.wasm` / `chi_sim.traineddata`（合计约 9 MB）。浏览器在 `file://` 下不会发这些请求，所以「零安装的单文件」和「可用的 OCR」天然互斥。

因此：

- 只想分析聊天记录 → 双击 `neurotide-lite.html`，不需要任何服务器；
- 需要截图 OCR → 解压 `neurotide-full/` 后双击 `open-neurotide.bat`（本机无需安装 Node）。

若用 `file://` 打开页面后仍去点截图识别，页面会明确提示需要通过本地 HTTP 服务运行，而不是在失败后悄悄尝试联网。

## 质量保障

解析、情绪计分、编码探测等核心逻辑都集中在 `src/utils/` 的纯函数里，因此可以用单元测试完整覆盖。

```bash
npm test          # 运行单元测试（Vitest）
npm run test:cov  # 单元测试 + 覆盖率报告
npm run lint      # 代码规范检查（oxlint）
npm run format    # 按 Prettier 规则格式化
npm run scan      # 入库前脱敏扫描（本机路径 / 个人邮箱 / 凭据）
npm run verify    # 一次跑完 lint + 格式检查 + 测试 + 构建 + 脱敏扫描
```

测试位于 `tests/`，覆盖：词条极性、否定与程度修饰、子串误命中屏蔽、四种聊天格式嗅探、非法日期与跳过行、月末回溯、GBK / UTF-16 / BOM 解码、数据集读写与容量守卫、CSV 转义与 JSON 备份往返、趋势与洞察的全部口径（缺口不参与均值、连续天数的日历相邻判定、区间对比在单侧无记录时不出结论等）、日历网格的几何与键盘导航（日期序列必须连续、`±1 格 = ±1 天`、边界不回绕、翻月按目标月收口、月份折成多块行时列号在块行内重新编号、块行间距与内容高度）、消息分批渲染的边界（首批条数、逐批续载、到末尾停住不越界、千分位不依赖运行环境 locale），以及分片解析与同步解析的逐字段一致性（含「1 行一片」把每条记录都切开、进度回调单调且首尾自洽、abort 能取消）。用例名即断言意图，改动 `src/utils/` 时可直接定位。

除单元测试外，发布前还会对 `dist/index.html` 做一次真实浏览器的端到端核验：以 `file://` 打开构建产物，确认「导入 → 写入 IndexedDB → 关闭浏览器 → 重新打开自动恢复」整条链路，并校验四个导出产物的实际字节（PNG 文件头与尺寸、CSV 的 UTF-8 BOM 与 CRLF、JSON 备份结构与原始文本）。无障碍部分同样在真实浏览器里断言：键盘游标能逐格移动并同步到 `aria-activedescendant`、隐藏网格的格子数与记录数一致、`aria-rowcount` 等于 7 × 月份块行数、画布高度等于内容高度而不铺满容器、开启色觉辅助与高对比后画布像素确实改变、窄屏下侧栏折叠为抽屉。规模化也在真实浏览器里量过：一天 5 万条消息时打开详情只渲染首批 120 条、滚到底自动续载下一批、DOM 保持在一千余节点；导入 5 万条期间无长任务、进度条确实出现并推进。

`scripts/scan-secrets.mjs` 用于提交前自查：命中本机用户名、绝对路径、邮箱或凭据时会报出文件与行号并返回非零退出码。本仓库为公开仓库，CI（`.github/workflows/ci.yml`）在每次推送和 PR 上执行上述全部检查。

## 隐私说明

NeuroTide 没有后端服务，也不会调用外部 API。用户选择的 TXT 文件和聊天截图只在当前浏览器中读取和处理，不会上传到服务器。截图 OCR 使用随项目提供的 Tesseract.js、本地 WebAssembly 引擎和简体中文模型；相关第三方许可证与模型来源说明位于 `public/ocr/`。

为了支持「下次打开继续看」，导入的原始文本会保存在浏览器的 `IndexedDB` 中（请留意以下几点）：

- 数据只在本机，可随时在左侧「本地数据集」中删除单份或一键清空全部
- 关闭「保存到本机」后不再写入，已保存的内容仍可单独删除
- 通过 `file://` 双击打开时，Chromium 内核浏览器把所有本地 HTML 视为同一个来源，因此同浏览器下的其它本地页面原则上也能读到这份数据。若在意这一点，请改用 `open-neurotide.bat` 启动的本地 HTTP 服务（`http://127.0.0.1` 是独立来源，不与其它本地文件共享），或用完即清空

请不要把包含真实个人信息的聊天记录提交到公开代码仓库。仓库中的聊天样例文件默认被 Git 忽略，应用内置的示例数据为程序生成的合成数据。
